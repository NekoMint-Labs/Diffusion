## 1. 希望用户完成的过程

用户在画布上看到一个可独立理解的观点，选中后决定是否深入阅读。Read 打开同一窗口右侧的固定阅读区；用户开始移动卡片或画布时，阅读区退出，手势继续。松手后保持画布状态，只有再次点击 Read 才重新打开。

首轮只改现有 Field 中 Thought/Ghost 的阅读体验。沿用 #80 的全文读取与后续操作路径、#81 的一次生成路径和用户纠正处理。Next 保持实验状态；Thread 的现有预览不纳入这轮布局改造。

## 2. 四种状态及转移

| 状态 | 卡片 | 阅读区 | 输入与相机 |
|---|---|---|---|
| 默认 | AI 卡片显示一个完整观点；保留未 Keep 标识。用户自己写的内容使用原措辞 | 关闭，无固定空白占位 | 新结果只出现，不自动选中或打开阅读区 |
| 已选中 | 沿用选中标记及 Keep/Ignore 等已有操作，显示 Read | 保持关闭 | 单击只选中。选中另一张卡片时关闭旧阅读区，不自动换成新卡片全文 |
| 阅读中 | 卡片仍在原位置；全文不写回卡片尺寸 | 固定在工作区右侧，显示该卡片完整原文、已有来源入口和适用的操作 | Read 是明确入口。阅读区内部滚动、选字和复制不传给画布 |
| 拖动／平移中 | 沿用现有拖动、分支移动和预览 | 收起并立刻停止接收输入 | 不取消 pointer capture，不重设相机或选中项，不调用焦点返回。松手后不重开 |

```mermaid
stateDiagram-v2
    [*] --> Default
    Default --> Selected: 选中卡片
    Selected --> Reading: 明确点击 Read
    Reading --> Selected: 关闭或普通 Escape
    Reading --> Selected: 选择另一张卡片
    Reading --> Interacting: 拖动或平移越过现有手势阈值
    Selected --> Interacting: 开始拖动或平移
    Interacting --> Selected: 松手或取消手势，阅读区保持关闭
```

### 阅读区的布局和收起

- 建议桌面宽窗口采用“左侧 Field + 右侧阅读区”的同级布局，阅读区宽度先试 360 CSS px，并允许文字自然换行。该数值是原型起点，最终由小窗口和缩放体验决定。
- 阅读区处于工作区布局中，不覆盖画布，也不使用卡片的坐标定位。打开后只改变 Field 的右边界；Field 的左上原点、相机变换与已有卡片坐标保持原值。不自动居中正在阅读的卡片。
- 收起时取消右侧占位，把宽度交回 Field。开始手势后应在同一交互边界完成收起，不做宽度过渡动画，不重新挂载 Field。ResizeObserver 只更新可见范围和布局测量；必须验证它没有引发被操作卡片的额外避让位移。
- 越过现有 `DRAG_THRESHOLD` 才按“开始拖动”处理；按下未移动仍属于选择。滚轮或触控板在 Field 上发生实际缩放／导航时同样收起；在阅读区滚动正文时保持阅读。
- 普通 Close/Escape 只关闭阅读区，焦点按现有协调器返回有效的 Read 入口，入口失效时回到 Field。输入法组合期间的 Escape 留给输入法。任何关闭方式都不恢复旧相机或旧选中项，也不取消正在生成的 Field 回答。
- 本次阅读的位置可在同一会话内按卡片 ID 与原文版本暂存。再次 Read 恢复滚动位置；原文修改、卡片删除或切换 Field 后失效。页面重启时阅读区保持关闭。

### 小窗口建议

当实际可用宽度不足以同时提供可读的 Field 和侧栏时，建议阅读区占据同一工作区的可用宽度，显示明确的“返回画布”。Field 实例保留，暂时不可交互；返回恢复原来的相机和卡片屏幕位置，不进行适配缩放。这是固定阅读区的窄窗口形态，尚需 A/B 和 reviewer 确认。

窄窗口不提供看不见的拖动操作。窗口重新变宽、关闭或返回画布，都不能自动打开别的卡片。若实机证明这种模式频繁打断空间操作，再调整断点或阅读宽度。

## 3. 共同内容约定

### 对用户显示什么

一个观点可以是判断、问题、假设或观察，必须独立表达主要意思，并保留改变意思的条件、否定和不确定性。正文提供完整说明，已有证据和来源沿用原来的权限、身份与入口。来源文字只说明它实际支持的内容；没有证据时保留“待验证”等原文措辞。

短回答本身已经完整时直接显示原文，不再生成同义的短标题。长回答有合格观点时显示该观点；为控制篇幅而截断的片段不能标作“完整观点”。120 字是当前实现的展示预算，不是观点质量标准，最终上限由 A 的语义约定和 B 的实机版面共同确定。

### 现有字段如何衔接

| 信息 | 当前来源 | 拟议用途及约束 |
|---|---|---|
| 卡片身份 | Ghost／Thought 的 `id` | 全文、观点、Keep 和操作目标始终绑定同一对象；不以文字相同推断是同一来源 |
| 完整文字 | `text` | 继续作为编辑、后续思考、历史／导出的正文输入；展示观点不能覆盖它 |
| 简短观点 | #81 的 `reading.point` | A 负责生成及语义约束；B 只展示通过检查、与当前全文版本一致的值 |
| 生成范围和已有来源 | Ghost 的 `scopeIds`、Keep 后已有的 `derivedFrom`、`origin` | 保留真实存在的引用；当前关联卡片的最新文字不冒充生成时冻结的上下文 |
| 未提交／已留下 | 当前 session／project 状态 | Keep 继续表达用户保留；不把它显示为事实认证 |

**建议先共同确认“可随 Keep 保存的观点元数据”这个窄合同。** 当前 #81 的 24 条内存缓存无法保证重启后恢复同一句观点。B 建议 A/Core owner 设计一个可选、受长度约束、绑定完整文字版本的记录，并明确它如何通过已有 Keep、存储和导入导出链路。具体字段名、匹配方式和迁移需求待共同确认；本提案没有自行修改 schema。

这项记录必须满足：

1. 缺少或不合法时，旧项目仍能读取完整正文；不能删除正文、重置数据库或自动调用模型补写。
2. 用户手写 Thought、原话提取候选保持原措辞。用户开始编辑时编辑器加载全文；提交编辑后旧观点立即失效，避免用户改了前提而卡片仍显示旧判断。编辑产生的历史遵循现有行为，不声称新增了永久版本档案。
3. Keep 通过既有命令边界保存完整正文、已支持的来源和合格观点；Ignore 不留下新的正式内容。Undo/Redo 同步恢复或移除整组信息。
4. 继续思考读取完整正文及现有有界上下文，不能把卡片观点当作压缩后的事实依据。
5. 重启和 JSON 导出／恢复后全文、可用观点和来源对应同一对象。不能只证明缓存里存在该值。
6. 模型的格式检查、限定词检查仅为保守防线；语义忠实性仍由真实模型样例和人工复核判断。

如果这轮暂时不批准持久化合同，可以先用现有缓存验证侧栏与手势，但应明确标为局部交互原型，不能据此宣称“观点卡片经过重启仍完整可用”。两种交付范围需要 A/B 先统一。

## 4. 卡片与全文的具体样例

以下全部是**人工设计样例**，没有经过真实模型调用。例中的用户条件用于共同评估，不是已发生的研究或用户访谈。

### Ask：直接回答当前问题

输入：“我每周只有两小时，想验证学生是否需要考前复习工具，又不能接触私人资料。先做什么？请给我一个方向。”

卡片：“先用公开例题做一次复习试用，验证学生是否愿意继续使用。”

全文：“先用公开例题做一次复习试用，验证学生是否愿意继续使用。在每周两小时、不接触私人资料的条件下，可以准备一道公开例题和一份简短复习说明，请愿意参与的人试用，并记录他们主动提到的困难。先不收集私人作业、成绩或身份信息。一次试用只能帮助发现问题，不能证明普遍需求。”

### Continue：形成下一步推论

已有观点：“先用公开例题做一次复习试用。”

卡片：“如果试用者只看答案，还需要确认他们是否学会了检查自己的错误。”

全文：“如果试用者只看答案，还需要确认他们是否学会了检查自己的错误。可以在自愿试用中追加一道类似的公开例题，请对方说明检查思路，不记录个人成绩。这样能进一步观察工具是否帮助复习；少量样例不足以证明学习效果。”

### Another Angle：改变观察角度

卡片：“复习困难也可能来自不知道先学什么，未必需要更多答案。”

全文：“复习困难也可能来自不知道先学什么，未必需要更多答案。可以先询问试用者如何安排复习顺序，再判断问题更偏向知识解释还是任务选择。这个角度改变了需要验证的问题；在取得反馈前，它仍只是另一种假设。”

### Diffuse：允许不同且有用的可能性

候选一：“只覆盖一章公开例题，可能更适合每周两小时的投入。”

对应全文：“只覆盖一章公开例题，可能更适合每周两小时的投入。先固定一个小范围，可以较清楚地记录准备、试用和修改所需时间。是否足够、是否有用仍需实际观察；这个建议不代表已经验证了需求。”

候选二：“先做复习顺序清单，可以检验困难是否主要在任务选择。”

对应全文：“先做复习顺序清单，可以检验困难是否主要在任务选择。用公开课程目录列出一个短顺序，请试用者指出不适合之处。它与提供答案是两个不同方向；是否值得继续，应由反馈决定。”

数量是上限。若只能提出一条有价值的可能性，就只显示一条；若内容会重复，允许结束并解释原因。不能为了凑条数把同一句话换说法。

### 不确定性与用户原话

用户原话：“我猜学生可能不知道该先复习哪一章，但我还没问过。”这张卡片保持原文。

后续 AI 卡片可以写：“‘不知道先复习什么’仍是假设，需要先向试用者确认。”全文应说明缺少哪类信息，以及可以如何询问。不能把它写成“学生的核心问题就是缺少复习规划”。

## 5. 现状中的三个实施约束

1. [ThoughtReader](../../src/ui/thought/ThoughtReader.tsx) 仍复用 `level="anchored"` 的 Surface；#81 的 [readingFocus.css](../../src/ui/thought/readingFocus.css) 把试用阅读器布局为居中浮层。固定侧栏需要成为工作区同级区域，单改 `right` 样式不够。
2. [useWorkspaceSurfaces](../../src/ui/workspace/useWorkspaceSurfaces.ts) 的 `closeSurface(false)` 只避免默认取消请求，仍会恢复 `returnPoint.camera` 和旧 selection。新阅读区关闭必须采用明确的“不恢复相机／选中项”路径，并继续由 [useTransientFocus](../../src/ui/workspace/useTransientFocus.ts) 统一处理键盘关闭后的焦点。不要全局改变 Thread、Deep Dive 等其他 surface 的返回语义。
3. [Field](../../src/field/Field.tsx) 在越过拖动阈值时设置 `dragging`，以 imperative 路径绘制逐帧动作。收起阅读区只需要一次手势起始通知，不能增加 React 的逐帧状态更新。窗口测量、可见范围、候选避让和焦点的副作用必须在集成测试里同时检查。

## 7. 验收方式

下表是待执行的验收计划，**本轮未运行应用测试、真实模型或原生桌面验收**。

| 场景 | 必须观察到的结果 | 验证层 |
|---|---|---|
| 默认 → 选择 → Read | 默认可理解观点；选择不打开全文；Read 打开右侧正文且不增加模型请求 | 挂载应用 + 人工阅读 |
| 阅读 → 拖动卡片 → 松手 | 手势不中断；卡片只产生预期移动；camera 不变；侧栏不重开 | 挂载应用 + Windows 指针 |
| 阅读 → 空白平移／触控板导航 | 侧栏收起；camera 仅产生用户手势的变化，不能回到打开前的位置 | 挂载应用 + Windows 触控板 |
| 阅读区滚动／选择文字 | 正文可读可复制；Field 不平移或缩放 | 挂载应用 + 原生输入 |
| Read → Close/Escape | 关闭不恢复旧 camera/selection；键盘焦点回到有效入口 | 挂载应用 + 键盘 |
| 用户编辑与中文 IME | 编辑器加载完整文字；组合键不误触关闭／提交；旧观点失效 | 挂载应用 + 物理中文 IME |
| Keep／Ignore／Undo／Redo | ID、全文、已有来源和合格观点一起按既有权限转换；阅读不形成额外历史 | Core/存储 + 挂载应用 |
| Keep → 退出 → 重启 → 导出／恢复 | 全文逐字一致，观点与其版本匹配，已有来源可追溯；不依赖内存缓存 | 存储 + Windows 安装包 |
| 新回答到达、失败、取消、迟到结果 | 不抢焦点或打开侧栏；旧请求不能覆盖当前卡片；收起侧栏不取消 Field 回答 | 挂载应用 |
| 深浅主题、Reduced Motion、390px 及宽窗口 | 无正文/控制溢出；阅读和返回可达；相机和坐标不因侧栏布局额外变化 | 截图核对 + Windows DPI |
| 四种动作、纠正和不确定性 | 有真实模型原文及失败样例；问答直接、续接有新增、角度有变化、发散不凑数 | 真实模型 + A/B 阅读复核 |

安装包需绑定完整提交、构建记录与 SHA-256。自动化检查证明工程行为；最终是否“一眼看懂，必要时深读，画布操作自由”需要在同一版本 Windows Preview 中体验。
