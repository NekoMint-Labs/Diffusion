# Diffusion 试用待修复问题

日期：2026-10-28。来源：A 方向参与者的单人试用反馈，经本人审阅调整后的问题稿。

当前应优先恢复基本操作的顺畅和可控。以下是待复现、排查和修复的问题线索，不是对当前 main 已确认缺陷的断言。反馈未记录精确应用版本、设备配置及完整复现步骤，主责成员应先补齐这些信息。分工和优先级为建议，尚未代表成员接单或团队批准。

产品方案及能力扩展另见[待讨论方案](待讨论方案.md)。本文件不将尚未决定的交互方案作为既定修复要求。

## 优先级与建议分工

本轮均暂列 P1，表示优先排查影响基本使用的问题，不表示已发生数据丢失或安全事故。复现后按影响范围调整。

| 编号 | 试用现象及影响 | 建议主责 | 协作与审核 |
| --- | --- | --- | --- |
| F01 | 信息遮住“继续想”等入口，点击后未正常执行，打断探索。 | C | B 核对命令和生成是否启动；A 验收流程 |
| F02 | 将两条信息拖近时触发关联操作，干扰单纯整理位置。 | C | B 核对是否调用模型及触发条件；A 确认用户意图 |
| F03 | “查证”本次未能正常完成，用户无法判断具体原因。 | B | C 完善状态与错误反馈；A 审核结果用途 |
| F04 | 拖动、缩放及“继续想”等操作卡顿，连续使用负担明显。 | C | B 区分模型等待与界面响应；A 组织连续使用验收 |

## F01 操作入口遮挡与点击失效

**排查内容：** 记录发生遮挡时的内容位置、缩放比例、窗口尺寸和选择状态；区分命中错误、焦点问题与命令已执行但结果未出现。

**处理目标：** 已显示为可用的操作入口应能正常触发，并给出明确反馈；内容重叠不应让用户失去继续操作的办法。

**验收：** 在相同布局、缩放和窗口条件下复测点击与键盘操作，核对动作只执行一次、焦点可预期、已有内容不被误改。C 提供实际界面记录，B 必要时补执行记录，A 完整走通探索流程。

## F02 移动引发非预期关联

**排查内容：** 分别记录“拖近”“释放”“连线”是否仅出现提示、写入关系或真正发起模型请求。不能把界面效果直接等同于已调用 AI。

**处理目标：** 用户单纯调整位置时，不应无明确意图就产生持久关系或启动 AI。若当前行为来自已有设计约定，应将调整方案提交 A、B、C 共同讨论；先保证行为可理解、可取消。

**验收：** 移近、移远、撤销和反复整理时，无非预期持久变化或模型调用；用户主动请求关联时功能仍可正常使用。自由连线的具体交互在讨论文档 D01 中决定。

## F03 查证无法完成或缺少解释

**排查内容：** 补记输入、来源、供应商及必要配置，区分配置缺失、网络不可用、搜索失败、正文未读取、模型失败和界面未显示。不读取或上传凭据。

**处理目标：** 条件满足时能完成实际查证；条件不满足时明确说明缺少什么、能否重试或停止。搜索结果不能冒充已读取的证据。

**验收：** 覆盖真实成功及相关失败路径，检查取消、重试和结果保留。B 留下可核对来源与运行记录；A 人工比对结论和原文，判断是否支持；C 确认状态和错误可被理解。请求成功不等于查证结论可靠。

## F04 连续操作卡顿

**排查内容：** 补记设备、应用版本、窗口尺寸、内容数量和典型操作序列。分别测量拖动缩放的界面响应、“继续想”的点击反馈和模型等待，不能笼统归因于网络或 AI。

**处理目标：** 优先保证输入、拖动、缩放的响应；模型运行期间仍能继续整理。等待、停止及失败状态应真实可见。

**验收：** 在同设备、同数据量与同操作序列下比较修复前后；覆盖少量内容和较多内容。C 提供可比较记录，B 核查生成期间阻塞，A 组织持续操作试用。具体性能目标在取得基线后共同确定，不虚设已达成指标。

## 人工审核与交付

- 主责成员先补充版本、步骤、预期、实际结果、发生频率和必要截图，无法复现时保留线索，不能直接标为已修复。
- A 负责判断是否真正恢复思考流程；B 负责真实 AI、查证及触发证据；C 负责输入、点击、焦点、拖动缩放和反馈。
- 工程测试可以证明执行和状态规则；查证质量、是否被打扰和连续使用是否顺畅仍需人工审核。
- 修复交付应包含复现记录、实际改动、相应验证和限制。本文仅提交反馈，不宣称已修复、已完成真人验收或已经形成团队共识。
