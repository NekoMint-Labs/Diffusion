# #48 满屏建议：紧凑入口与临时阅读面板

状态：设计提案，待 @usehahade 核对 #49 共用规则、@onedotmint 确认。2026-10-11。

依据：[Operator clarification](https://github.com/NekoMint-Labs/Diffusion/issues/48#issuecomment-6108409334)。原来的自动展开列表已被否决；常规就近放置继续由 PR #57 独立交付。

## 建议的交互

1. 优先在来源附近显示正常 Ghost。只有安全局部空间不足、结果进入现有建议阅读集合时，底部出现「建议 N」。新结果只更新数量并作一次简短无障碍播报，不打开面板、不抢焦点。
2. 在 1280×720 草图中，「总览」「建议 N」是左下角并排的两个 36px 高按钮，距左边 24px、底边 16px，间隔 8px。没有通栏背景、额外一行或 Field 高度预留。写作入口继续位于中部。
3. 点击「建议 N」打开其上方 420×320px 的临时面板，距左边 24px、底边 68px。标题和关闭按钮固定；正文、完整来源、留下/忽略位于内部滚动区，长中文不截断。窗口较小时限制在实际可用区域内，不超过窗口宽度减 48px、可用高度减去写作/入口安全区。
4. 面板只在显式打开时覆盖局部画布。点击同一入口、关闭或非 IME 合成态下的 Escape 收起；点击写作区先收起面板，再进入原有写作流程，保留当前草稿。没有 backdrop、焦点循环或自动相机移动。
5. 留下/忽略复用现有动作、身份、坐标及来源关系，不复制结果、不自动重新排布。留下后，当前阅读会话保留同一结果的「已留下」全文回执；关闭阅读会话后移除回执，不再计入待处理数。忽略只删除对应待处理项。待处理项归零且关闭后，「建议」入口隐藏，焦点回到仍可用的总览入口或 Field 原有焦点目标。

固定空间的草图尺寸是待确认的产品选择。420×320 覆盖 1280×720 画布约 14.6%，属于主动打开的临时覆盖区域；Field 的布局边界不变。两个关闭态按钮合计仅约 122×36px，不预留整个底部条带。

## 与 #49 共用的约定

- 一个临时阅读位置，最多一个面板。打开建议关闭总览，打开总览关闭建议。两个入口始终保留自己的归属和标签，不另设第二个 dock。
- 建议打开后焦点进入关闭按钮；总览打开后进入查找输入框。Tab 沿原生顺序继续到操作按钮和其他应用控件，不困住焦点。Escape 在中文合成态中交给输入法；非合成态关闭后返回触发入口，入口消失时使用原有 Field 焦点目标。
- 打开、切换、关闭、滚动建议本身均不改相机、选区、折叠及持久化坐标。#49 的显式定位/返回由 @usehahade 在自己的方案中定义并实现，进入前相机及选区的恢复约束继续有效。
- 写作和 ReadWindow 优先使用现有入口；若写作区因界面缩放/窗口尺寸增大，面板需限制在它的安全区上方。空间不够时缩小内部滚动区域，不制造新的全宽 dock，也不修改 Field inset。
- 总览草图用于核对共享位置、关闭/返回控件和写作安全区；其查询、临时定位及返回逻辑尚未由 #49 owner 确认，不能据此声称已完成 #49。

## 2026-10-12：供 #49 核对的协作清单

这次补充把已提出的共享规则和仍待 C 决定的导航行为分开。原三态草图、尺寸和原型不变；以下是待确认约定，不表示双方已达成一致。

| 事项 | B（#48）的提案与边界 | 需要 C（#49）核对 |
| --- | --- | --- |
| 收起占用 | 左下两个 36px 高入口；不预留通栏高度，不修改 Field inset | 总览能否共用该入口区域；小窗口和界面缩放是否需要收紧间距 |
| 展开与互斥 | 建议上限 420×320px，内部滚动；任一时刻最多一个展开面板 | 总览的实际尺寸及同一区域内的切换方式；不产生第二个 dock |
| 写作与必要操作 | 写作/ReadWindow 优先；建议关闭不提交或丢弃草稿；不遮住 Stop、关系决策等必要操作 | 总览/Find 的关闭和焦点规则是否与写作一致；空间不足时如何保持这些动作可用 |
| 焦点与 Escape | 建议打开聚焦关闭按钮；关闭回入口；合成态 Escape 交给输入法；Tab 不形成焦点陷阱 | 总览打开的输入焦点、切换后的焦点、入口消失的回退目标，以及 Escape 的唯一归属 |
| 空间与来源 | 打开/切换/关闭建议不改变相机、选区、折叠、正式坐标；来源取每个 Ghost 冻结的 scopeIds | 导航不能把建议来源替换为当前选区，也不能重新放置已交给用户的 Ghost |
| 关闭与返回 | 关闭建议只收起建议阅读面板、结束本次留下回执并还回焦点，不调用导航返回 | 明确总览/Find 的“关闭”是否同时返回，以及独立“返回原视图”的入口；不能把 B 的普通关闭误接到相机恢复 |

当前实现依据：`RootReview` 与 `SuggestionReview` 各有本地开关；`useWorkspaceSurfaces.closeSurface()` 则会恢复相机/选区，默认还会处理 AI 取消。因此，新紧凑面板不能仅因为同名“关闭”就照搬整段退出行为。建议的普通收起/切换不取消正在进行的 AI 请求，也不隐式调用导航返回；Stop 与主动返回仍是各自明确的用户动作。具体代码组织由实现者选择。

### C 侧仍需给出的导航说明

按 #49 当前要求，用户应能完成：**总览/Find → 输入查询 → 显式定位 → 返回原阅读视图**。B 不在本 PR 实现或代替 C 决定这段导航。请 C 在 #49 或本 PR 补充四点即可：

1. 首次临时定位前，何时记录原相机/选区；同一会话反复定位时是否保留同一个返回点。
2. 关闭、Escape、切换到建议、进入写作，与主动返回原视图之间的区别；哪个动作会恢复相机/选区。
3. 返回时如何保持缩放、显式折叠及存活的选中对象；目标被删除或 Find 无匹配时如何回到可用焦点。
4. 最终总览/Find 尺寸及在 1280×720、小窗口和界面缩放下的空间规则。

上述说明完成后，可将 #48 与 #49 的可见设计一起交给 @onedotmint 确认；不要求先合并 #57/#60/#61，也不要求先合并本 docs 草案。实现 PR 仍各自经过独立 review。
