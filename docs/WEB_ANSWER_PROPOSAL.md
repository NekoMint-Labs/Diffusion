# 联网问答改进提案（尚未实现）

2026-10-12。当前查证可以搜索候选、阅读来源，并在明确操作后评估已读段落是否支持一个说法。它不是完整的联网问答。“你好”等短词会得到词典、翻译表格等候选；清理排版只能改善可读性，不能保证答案相关或正确。

## 推荐的实现方向

1. 区分联网问答与证据查证。问答回应问题；查证保留支持、反对、部分支持或证据不足的判断。意图含糊时澄清问题，不直接把关键词当完整问题。
2. 在用户明确启动后执行：搜索候选 → 选择相关来源 → 读取正文 → 筛选与问题相关的原文段落 → 使用已配置的真实模型生成带引用的回答。正文缺失、无相关证据或来源冲突必须明确说明。模型服务也需要可用配置；没有搜索 Key 不等于模型服务免费。
3. 原始来源、实际已读范围、段落 ID、时间和引用可核对；摘要不升级为已读证据。回答所引用的段落必须来自实际读取的正文，不能仅凭存在一个引用 ID 就声称内容正确。网页内容视为数据，不执行其中的指令。
4. 不自动重试、绕过凭证要求或更换搜索来源。请求限量、有超时和取消；断网明确提示。是否引入新问答入口与查询改写，需与 #22/#51 任务范围及产品设计协调。

## 来源选择

| 选择 | 用途与限制 |
| --- | --- |
| 保留当前来源，先改善问答流程 | 推荐先做有界本地实验；不要求新增搜索 Key，但仍受现有来源质量和可用性限制 |
| 正规 Tavily / Brave API | 结构化结果、正文或面向模型的上下文；需要各自可用 Key，费用与额度以服务方为准；换 API 不保证答案正确 |
| 自建 SearXNG | 可选择多个上游引擎并输出 JSON；需部署维护及检查上游访问条件，不能保证没有限流或验证码；公共实例常禁用 JSON，不能当作稳定后端承诺 |

官方资料：

- [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)
- [Brave LLM Context](https://api-dashboard.search.brave.com/documentation/services/llm-context)
- [SearXNG Search API](https://docs.searxng.org/dev/search_api.html)

## 验收方式

固定一批中文解释、最新信息、软件操作、来源冲突、无结果及含糊问题，保存改前/改后结果。分别检查：问题是否被正确理解、回答是否相关、关键断言是否被引用正文支持、是否隐瞒冲突和不足、原文能否核对。另测无模型配置、断网、超时、取消和迟到结果。

浏览器模拟服务回归验证流程；真实搜索与真实模型复测验证可用性和内容质量，二者分别记录。本提案没有实现新问答模式、部署 SearXNG 或新增搜索 provider，也没有承诺所有问题都能得到正确答案。
