## 已在源码确认的行为

- src/shared/answerPreview.ts：首段优先，否则取前 119 个 Unicode 字符加省略号；它是显示摘录，不是语义总结。
- src/ai/prompt.ts：已经要求重点先行，但生成是否遵守仍要真实模型验证。继续追加提示词不能提供结构保证。
- src/ui/thought/ThoughtView.tsx：AI 候选先经过 answerPreview，再经过视图缩放摘录；完整原文仍用于阅读和后续操作。原文拆分候选与普通 AI 候选走不同显示分支。
- src/ai/context.ts、lineageContext.ts：选中内容为主体，来源链与关联可能提供背景。默认不等于读取其他聊天；也不能把所有历史背景都当成当前目标。

## 本轮实现

1. protocol.ts：独立重点协议。一次结果包含 decision、point、conditions、detail、consideredSelectionIds、basis。重点最多 120 个 Unicode 字符；关键成立条件始终可见；依据只允许精确引用实际提供的内容。
2. prepareInput 复用正式 compileContext，记录实际 selection/background 和截断信息；不更改正式编译策略。
3. run.ts：五种离线上下文样例、28 项断言，以及每次最多一个真实模型生成请求的对照入口。无自动重试。发起前保存上下文，完成后保存原始输出、耗时和服务返回的模型身份；校验失败保留原始模型值。网络错误只存失败类型，避免记录凭据。
4. focus-demo.html：可切换“结论＋关键条件”“原文重点标记”“阅读边栏”，支持展开详情。原文标记使用图 1 的文字；新重点与边栏示例为人工编写。
5. verify-demo.mjs：只测独立样例，不运行完整产品浏览器套件。

字段齐全、选中 ID 齐全和引用逐字匹配，只证明结构与来源位置成立，不能证明理解正确、推理正确或结论真实。没有实现基于关键词的自动“聪明摘要”，也不把截断失败包装成成功。
