# 观点卡片与固定阅读区：本地原型

日期：2026-10-27。基线：PR #82 `6e41814`，含 PR #81 `79a4844`。用户在本对话明确授权开始升级；本轮未向协作者发送消息，未宣称团队共同验收。

## 已实现

- 新开关 `propositionTrial=1`，沿用原 Field。旧 `readingTrial=1` 阅读方式保留。
- 同一次生成补充独立观点约束；完整正文和已有来源沿用原权限及校验。缺少合格观点时明确显示正文预览，不追加调用模型。
- `proposition: { version: 1, text, original }` 是可选展示记录，绑定逐字完整正文。生成 Ghost、Keep、撤销、重做、JSON 恢复与 IndexedDB 重新打开均覆盖。不是事实认证，不能替代全文进入继续思考上下文。
- 内容编辑及结晶改写清除旧观点；取消无变化编辑沿用原行为。显式手动提炼只在生成内容上提供，通过用户命令保存观点，保留原文；来源及用户原话不自动提炼。
- 导入/恢复保留全部原项目校验，只丢弃不合法或正文不匹配的可选观点，输入对象不被原地改写。旧记录缺字段仍可读取；现有数据库表/索引和 schemaVersion 不变。旧客户端不理解观点时不保证保留展示值，全文仍是权威内容。
- 与本地合同早期草案的 SHA-256 方案相比，原型选择有上限的原文副本做同步精确匹配，避免引入加密算法或异步 Core 校验。代价是存储体积增加，可能更早触及已有 10 MiB JSON 恢复预算；未提高此预算。
- 宽窗口固定 360 CSS px 右侧阅读区，与 Field 同级。打开只收窄 Field 右边界，不移动相机、卡片或重新挂载 Field。选中卡片不自动打开阅读区。
- 普通关闭/Escape不取消生成、不恢复旧 camera/selection，焦点沿用既有协调器；手势阈值触发收起，不恢复焦点、不释放原 Field pointer capture，松手不重开。滚轮缩放同样收起，阅读区内滚动不传给画布。
- 窄于760px改全宽阅读，Field实例保留但隐藏，提供返回按钮；模拟IME组合Escape不关闭。物理输入法与触控板仍需Windows体验。
- 阅读位置按ID和原文在24项会话缓存中保留，切Field清空；不是项目持久化状态。

## 试用方式

先在旧页面留下想保留的候选，再打开：

`http://127.0.0.1:4175/?locale=zh&readingTrial=1&propositionTrial=1`

1. 选一张AI建议，点击阅读原文。正文应出现在固定右侧，不再居中盖住画布。
2. 拖动一张仍可见的卡片，或在画布空白处平移。阅读区应收起，拖动继续；松手不重开，视图不跳回旧位置。
3. 再点阅读原文可重开。先留下新产生且有观点的建议，刷新后该观点应仍保留；打开全文核对原文完整。
4. 旧长卡片没有持久化观点时，显示正文预览。可以显式提炼一次，再刷新核对；不会自动遍历旧卡片或收费补写。
5. 双击编辑应载入全文。实际修改并保存后旧观点消失，撤销恢复原正文和观点。手工原话保持原措辞。

未留下候选仍是临时数据。新开关不提供旧会话缓存的自动转存，也不保证真实模型每次都给出合格观点。

## 用户试用观察（2026-10-28）

用户要求一个不同的新方向：不再讨论完成标准，想弄清楚先复习哪一章；时间不限，并保留不做工具、不安排学生试用、不接触私人资料。截图显示 DeepSeek `deepseek-flash` 给出了两条候选：一条观察首次需要翻回教材的位置，另一条按后续章节的交叉引用次数排序。两条都转向章节优先级，并承认这些线索不能证明个人实际卡点；“停顿/引用次数”只是尚待验证的代理指标。输出标注未经事实核验。

明确要求“一个不同的新方向”却得到两条候选。原因是单数解析未覆盖“不同的新方向”这一自然表述。解析现已补上该形式，并由单元测试覆盖从选中的用户修正中提取数量、将非遵循数量的响应限制为一条；构建通过。修复后的行为尚未由真实模型请求复测。此次是一个可用方向的正例，同时暴露候选数量遵循问题；单次输出不代表模型稳定性。
