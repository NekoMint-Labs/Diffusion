## 约5分钟的演示顺序

推荐先演示确定性工程能力，再展示已有真实样本；没有必要现场不断请求模型等待一个漂亮回答。

1. 打开固定集成版本，在新建的演示Field手写两条想法并编辑一条，展示内容属于用户、可继续修改。不要导入私人Field或清理已有数据。
2. 展示一条AI候选的选择、阅读原文和Keep：候选与已保留内容区分，短文直显、长文观点/预览与全文区分。若采用预先准备的模型输出，必须明确称为“已采集真实样本”；若用Demo或注入，明确称为“演示响应”，不可混称现场真实调用。
3. Keep后确认保存，再刷新、重读全文；可演示一次Undo/Redo。说明完整原文始终保留，观点不是经核验的事实。
4. 在可丢弃的手写演示内容上展示Fork、修改并Bring回主线；确认新旧卡片分开可读、来源保留。需要定位时按现有操作，不宣称连线体验反馈已经修复。
5. 打开下方三轮证据中的一组成功和一组失败，解释“我们验证了哪些路径、模型在哪些地方仍不可靠”。最后说明表达指导仍默认关闭，实验分支不是稳定版。

若只能留两分钟：只演示“阅读/Keep/重读原文”及一组真实对照，明确局限；不要把所有功能塞进演示。
