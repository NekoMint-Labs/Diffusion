# Field 观点卡片：真实模型对比记录模板

状态：待执行。本文没有真实模型输出，不能作为模型质量通过证据。

用途：配合 [B 侧交互提案](FIELD_PROPOSITION_READER_PROPOSAL.zh-CN.md)，由 A 提供真实输出，B 复核卡片含义和全文阅读体验。先确保完整输出被保存，再评价它是否有用。人工设计样例不能填进“真实输出”栏。

## 共同输入

第一组使用以下公开、人工编写的测试话题，不需要私人资料或搜索：

> 我想验证学生是否需要一个考前复习工具。每周只有两小时可以投入，不接触学生的私人作业、成绩或身份资料。目前还没有访谈或试用结果。

将这段原话保存为用户 Thought。每个动作的 baseline 与 candidate 使用内容相同的 Field 快照、相同选中范围和相同已有来源；记录 ID 映射和快照标识。两次输出各自在隔离的副本中生成，不能把 baseline 的回答混进 candidate 的上下文。

| 动作 | 明确输入／操作 | 重点核对 |
|---|---|---|
| Ask | “在这些条件下，先做什么？请给我一个方向。” | 是否直接回答；一个方向能否成立；是否保留两小时和隐私条件 |
| Continue | 选中共同输入，运行继续想；使用双方约定的相同数量上限 | 是否增加一个推论、约束或可检查的下一步；是否只是重述原话 |
| Another Angle | 选中共同输入，运行换个角度 | 是否改变问题的看法、假设或比较维度；不能只换措辞 |
| Diffuse | 选中共同输入，运行发散；记录实际步骤和数量上限 | 候选之间是否不同且有用；少于上限或没有新结果是否合理；不把数量当质量 |

再增加两组挑战条件，沿用实际用户回应链，不用改写旧卡片制造结果：

1. 旧前提是“每周四小时、作业辅助”；用户新回应改成“两小时、考前复习”，明确保留隐私条件。核对新旧条件的适用性和选中范围。
2. 用户补充“我刚才只是设想，还没有确认学生存在这个问题”。核对观点和全文是否继续保留假设性质；相同观点已出现时再 Continue，保留重复、无价值、拒答或暂停等真实结果。

## 并排评阅

每种动作至少展示一组完整对照，注明样本有限。A 与 B 分别回答下列问题，并标出对应原句：

- 读卡片时能说出它提出的具体意思吗？独立读它与阅读全文后，对条件、否定和确定程度的理解是否一致？
- Ask 有没有正面回答？Continue 新增了什么？Another Angle 改变了什么维度？Diffuse 中哪些候选值得保留，哪些只是重复？
- 有无凭空出现的人群结论、来源、证据或已经完成的实验？有无把用户假设改成事实？
- 改变前提后，哪些旧限制仍适用，哪些已经被替换？模型是否沿用了失效建议？
- 若愿意 Keep，理由是什么？若 Ignore，具体是哪句话或哪项缺失使它无用？

结论使用“这组样例中更好／相当／更差／无法判断”，附依据。格式合法、单次截图、自动化全绿或更短的字数都不能单独作为模型质量结论。
