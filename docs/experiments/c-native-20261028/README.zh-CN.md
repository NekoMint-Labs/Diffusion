## 发现 N01：Bring 新卡覆盖已有建议卡

优先级建议 P2。Bring 会将选中的分支内容添加为独立卡片；本次新卡的落点与已有 Demo 卡重叠，影响阅读和选择。正文未丢失。

本轮触发路径（尚未统计从初始状态独立重现的次数）：

1. 导入公开三卡测试项目。
2. 在手写长文上执行 Demo 换角度，选择一个方向，留下生成的建议。
3. 创建分支，给手写长文追加“ 分支补充：先做一个小例子再决定。”。
4. 比较分支与主线，选择已改变的手写卡，点“将选中内容带回主线”，再回到主线。
5. 新 Bring 卡覆盖已有建议卡左侧；关闭重开以及导出恢复后仍保持重叠。

持久化坐标证据：

- Bring 操作时使用最大化窗口，工具捕获区域约 1440×852；最终导出的相机为 x=122.66666412353516、y=74.82696266069661、zoom=1。原始 fixture 相机为 0/0/1，因此仅照上述步骤冷启动重做，不保证得到相同落点；恢复本轮最终导出可重现保存的重叠状态。
- Bring 卡：x=472.33333587646484，y=335.6469963084196。
- Demo 卡：x=740，y=337。
- 两张卡均采用约 328px 的 wide 宽度，横向交集约 60.33px，顶部仅差约 1.35px。

静态复核：`src/core/world.ts` 的 `bringToMain` 按传入点与固定网格放置，未检查既有卡片占位；`ForkSurface` 直接传入 `actions.anchor()`。此条是界面落点问题，不能描述为正文或来源标记丢失。本轮保留原版本作为复现依据，未修改产品实现。
