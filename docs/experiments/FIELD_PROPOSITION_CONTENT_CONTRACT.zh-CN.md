# Field 观点与全文：内容约定草案

日期：2026-10-27。状态：用户已授权据现有提案实现本地可选原型；尚未宣称团队共同验收、真实模型质量提升或 Windows 安装包验收。

依据：[交互提案](FIELD_PROPOSITION_READER_PROPOSAL.zh-CN.md)与[模型对比模板](FIELD_PROPOSITION_MODEL_COMPARISON.md)。基线为 PR #82 的 `6e41814ebbc067da1dcaed02db8f65ad8d922d14`，包含 PR #81 的 `79a4844`。PR #82 的文档批准只认可提案作为协作起点，不能解释为本合同、模型质量或原型已经验收。

## 1. 内容与权限

- `text` 始终是完整正文。编辑器、继续思考、历史及导出使用它；观点不能替代正文进入上下文。
- 观点是一句独立可理解的判断、问题、假设或观察。改变主要意思的条件、否定和不确定性必须在观点里；细节、论据和局限放在正文里。
- 用户原话及原文提取候选维持原措辞；不自动改写成模型观点。
- 读取全文是本地操作，不调用模型、不 Keep、不形成额外内容历史。Keep 表示保留，不表示事实认证。
- 生成仍经既有 action/schema、权限、范围、取消、质量及重复检查；补充观点不能扩大模型的修改权。

## 2. 提议的最小元数据

建议在合格的生成 Ghost 及显式 Keep 后的 Thought 上增加一个可选展示记录；名称和存储版本仍待共同确认：

```ts
proposition?: {
    version: 1;
    text: string;
    original: string;
}
```

- `text` 非空，先沿用最多 120 个 Unicode 字符的试用预算。这个数是阅读预算，不是质量结论；不能靠截断修复超限观点。
- 本地原型采用 `original` 保存绑定时的完整正文，直接逐字比较，不先 trim、换行转换或 Unicode 归一化。原文上限沿用 20,000 字符；不信任模型返回的绑定值。
- 与先前草案的 SHA-256 方案相比，精确正文绑定增加了存储体积，但可在同步、跨平台 Core 校验中判断匹配，避免异步摘要计算穿过取消、历史和导入边界。没有新增密码算法或库。相同文本不代表同一对象，操作仍按 ID。
- 该字段只是版本匹配，不是事实核验、签名或防伪机制；导入者可以同时改写正文及绑定值。
- 生成入口在创建候选前同步完成绑定，后续仍走原 signal/ticket/范围检查。Core 不引入 WebCrypto/文件系统调用。
- 保存正文副本会让部分项目更早达到既有 10 MiB JSON 恢复上限；本轮不提高该预算。正式采用前应结合真实项目体积评估是否改为经过验证的摘要绑定方案。
- 来源和模型身份沿用已有 provenance，不把当前关联问题的最新文本冒充生成时快照，也不捏造缺失的实际模型身份。

当前在 `propositionTrial=1` 本地原型中接入生成、Ghost/Keep、用户命令、编辑失效、校验和存储；模型仅返回观点文字，应用建立绑定。测试结果和限制见原型报告，不能由本文件代替运行证据。

## 3. 状态转换与回退

| 动作 | 正文与观点应如何处理 |
| --- | --- |
| 返回短正文 | 原文已可直接理解时直显，不要求额外观点 |
| 返回长正文及合格观点 | 保留全文，显示与其版本匹配的观点 |
| 观点缺失、超限、不合法或显式限定语检查失败 | 保留全文；诚实标注“正文预览”，片段不能冒充完整观点；Read 仍可达，不自动补请求 |
| 用户显式手动提炼 | 只处理该全文，计一次请求；成功时绑定当前版本，正文不改；失败或取消保持原有可读状态 |
| Keep | 通过既有用户命令保留同一 ID 的全文、已有来源和合格观点；不能凭相同文字合并对象 |
| Ignore | 不增加持久化记录 |
| 开始编辑 | 编辑器载入全文；输入法组合和撤销规则沿用既有所有权 |
| 提交编辑 | 同一用户命令移除旧观点；取消编辑则保留原状态。编辑器没有实际文字变化时沿用既有取消行为；实际提交 thought.edit（包括显式同文命令）都会清除旧观点 |
| Undo / Redo | 按既有历史边界一起恢复/移除正文、来源和观点；不能只有正文回退而观点仍来自新版本 |
| 重启 / JSON 恢复 | 验证版本、结构及正文绑定后使用观点；阅读区默认关闭，无自动模型调用 |
| 删除 / 切换 Field | 清除对应临时阅读状态，不删除其他内容 |

继续保留明确标注的正文预览作为失败回退，意味着首轮不能宣称“所有长文一定有完整观点”。真实模型是否能稳定产生观点，是单独的验收项。

## 4. 兼容性与实现边界

1. 旧记录缺少观点时应完整读取原文；不得清库、改原文或自动调用模型补写。
2. 外部导入在原有正文/权限/结构校验继续有效的前提下，可以丢弃不合法的可选展示字段并报告回退；不能捕获整个项目错误后跳过原校验。
3. 需核对实际存储与 JSON 格式后再决定版本策略。现有 `schemaVersion: 1` 不能自动证明旧版客户端会保留新增字段，也不能据本草案宣称无需迁移。旧版重导出丢失观点时，全文仍应可读。
4. 观点不含布局、侧栏开关、滚动位置或相机信息。这些状态由 Field/UI 会话持有，不进入项目数据。
5. 内容提交只改生成、数据转换与校验；固定侧栏和手势由独立交互提交负责，避免同时修改 ThoughtView/Workspace 的同一行为。
6. 此次用户授权允许实现可选原型；字段和回退属于原型约定，正式合并仍需团队审核，不能将本地通过写成产品验收。

## 5. 真实输出对比的最小执行方案

先沿用已有模板中的公开测试话题，不读取用户私人 Field、不搜索。

- Baseline：#80 `5ab6b20`；Candidate：#81 `79a4844` 并显式启用 `readingTrial=1`。两边使用相同 Field 快照、选中范围、用户输入、模型和思考深度，分别运行于隔离副本。
- Ask、Continue、Another Angle、Diffuse 各一组前后对比，共 8 次生成；Another Angle/Diffuse 限单步单次，避免把调用次数差异误当质量提升。
- 再追加“作业辅助/四小时 → 考前复习/两小时”及“还没确认问题存在”两组对比，共 4 次。合计计划 12 次真实生成，无自动重试。
- 执行前确认可用的模型连接及两组实际请求配置一致；记录请求模型、服务报告的实际模型，未知则写未知。不能从标签推断已连接或借读用户密钥。
- 记录每次完整正文、实际卡片展示及是否为预览回退；保留空结果、拒答、超时、重复和无价值输出。模型生成和后续摘要若额外调用，必须计入次数，不能藏在一次动作里。
- 判断 Ask 是否回答、Continue 新增什么、Another Angle 换了什么维度、Diffuse 是否有用且不同；单独比较观点与全文的条件和确定程度。
- 本方案是行为组合对比：#80/#81 有多处变化，不能归因为某一条提示或单一模块的因果效果。单样本无法证明稳定提升。

本轮没有执行这些真实模型请求，也没有把人工设计样例填入真实输出表。完成合同讨论和真实样例评阅后，再构建原 Field 的最小集成原型。
