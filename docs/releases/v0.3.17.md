# v0.3.17 — draft release notes

**Not published. Prepared November 4, 2026 for final review and Windows acceptance.**
The currently published stable release remains v0.3.16. This document is not a
download announcement or proof that an installer has passed acceptance.

## Changes since the published stable release

- Consolidates Field reading from [#96](https://github.com/NekoMint-Labs/Diffusion/pull/96):
  compact optional points with full originals, one fixed reader, and explicit
  Keep/Ignore/Fork/Bring. Original wording remains authoritative for thinking,
  persistence and portable export.
- Points survive Keep and recovery when they still match the original. Editing
  invalidates an old point; Undo/Redo restores matching state. Historical AI
  origin remains visible while user-edited wording is marked separately.
- Brings new cards into clear space without moving existing cards or the camera.
  Handwritten Fork/Bring cards do not become AI-generated merely from lineage.
- Keeps the 120-character opening guidance specific to Field. Thread, Deep Dive,
  Probe and Organize retain their separate response behavior.
- Prepares consistent v0.3.17 manifests and profile-specific installer notes with
  exact-source/checksum receipts. Stable identity, data and credential namespaces
  are preserved; Preview remains an isolated internal testing option.

The standalone Next workspace is excluded. Free Links #94 remains a separate
Draft. Plain-answer experimentation is not enabled. #75/#76 remain deferred.
This preparation adds no new product feature or data-schema migration.

## Known limits and release gate

Historical model trials showed mixed answer quality; this release does not claim
to solve unsupported assumptions or establish a new model default. Optional
metadata may be dropped by older clients. Old cards cannot retroactively prove
whether their wording was edited. Large-bundle warnings remain visible.

Automated tests, NSIS builds, installed Windows checks and live-model acceptance
are distinct. The final source must pass CI/E2E/native/packaging checks. Actual
installation/upgrade, retained Fields and credentials, JSON recovery, Chinese IME
and a bounded real-provider workflow are still required on the exact package.
See [stable installation and acceptance](../WINDOWS_INSTALL.md).

After review, acceptance and separate merge/publication approval, build from the
final main SHA and publish the installer with its SHA-256, `source.json`,
`INSTALL.md` and final release notes. A PR acceptance package is not a published
release and must not be represented as the final-main build.
